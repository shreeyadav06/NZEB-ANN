# Comprehensive Analysis Report: NZEB Climate-Aware Transfer Learning

## 1. Project Objectives
The objective of this project was to investigate whether **Transfer Learning (TL)** can solve the "cold start" (data scarcity) problem when predicting building energy consumption for newly built Net Zero Energy Buildings (NZEB) across different ASHRAE climate zones. Specifically, we aimed to prove that a model trained on a data-rich source climate can be effectively transferred to a data-scarce target climate, outperforming models trained from scratch. We also aimed to identify the exact "crossover point" at which sufficient target data makes training from scratch equally viable.

## 2. Methodology & Implementation (How We Did It)

### 2.1 Data Collection & Preprocessing
- **Dataset:** We utilized the ASHRAE Great Energy Predictor III dataset, specifically extracting electricity meter readings (Meter 0).
- **Selected Sites:** We isolated three distinct climate zones:
  - **Site 2 (Tempe):** Hot/Dry (Zone 2B)
  - **Site 4 (Berkeley):** Warm/Marine (Zone 3C)
  - **Site 15 (Cornell):** Cold/Humid (Zone 6A)
- **Feature Engineering:** We implemented rigorous temporal encoding (Sine/Cosine transformations for hours, days, and months to capture cyclical weather patterns). We also applied log-transformations to skewed continuous variables and scaled all features using `StandardScaler` to ensure stable neural network convergence.

### 2.2 Model Architecture (Artificial Neural Networks)
- We built deep feed-forward Artificial Neural Networks (ANNs) using `TensorFlow/Keras`.
- **Topology:** The network architecture consisted of 4 hidden layers `[256, 128, 64, 32]` utilizing `ReLU` activations.
- **Optimization:** We used an Adam optimizer with a learning rate of `1e-5` for baseline training and `1e-4` for transfer learning, utilizing `EarlyStopping` (patience=10) to prevent overfitting.

### 2.3 Experimental Phases
1. **Phase 1 & 2 (Setup):** Data parsing, cleaning, scaling, and feature generation for 800k+ rows of data per site.
2. **Phase 3 (Baseline/Scratch Models):** We trained models completely from scratch on each site individually using 5-Fold Cross-Validation. This established the upper bound of performance for each region when 100% of the data is available. We trained 5 models per site (15 models total).
3. **Phase 4 (Transfer Learning Matrix):** We performed transfer learning between secondary scenarios (Berkeley to Cornell, Tempe to Berkeley). During transfer, we **froze the first 3 layers** of the pre-trained source model, allowing only the final layer to adapt to the new climate's specific nuances.
4. **Phase 5 (Data Efficiency & Crossover):** This was our primary experiment (Tempe -> Cornell). We simulated data scarcity by restricting the target training data to distinct fractions: **5%, 10%, 20%, 30%, 50%, and 100%**. We trained both Scratch and Transfer models on these fractions, repeating the process across 3 different random seeds (42, 123, 456) to ensure statistical validity.
